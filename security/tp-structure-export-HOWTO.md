# تصدير بنية Staging: تعليمات التشغيل (v3) · 2026-11-11

## السبب الحقيقي للخطأ `relation "if" does not exist`

**السبب ليس في الاستعلام نفسه، بل في خيار «RLS Enabled» داخل SQL Editor.**

1. عندما يكون الخيار مفعّلاً، يقرأ SQL Editor نص الاستعلام قبل إرساله، ويبحث عن عبارة `CREATE TABLE`. عند كل جدول يجده، يضيف أمراً يفعّل RLS عليه.
2. النسختان v1 وv2 تحتويان نصياً على العبارة `create table if not exists %s` (داخل قالب نصي، وليس كأمر). بهذا تعرض النسختان كيف يُبنى الجدول، لكنهما لا تنشئان شيئاً.
3. نمط البحث الذي يستعمله Supabase Studio نفسه (من ملف `apps/studio/lib/sql-event-parser.ts`) قرأ هذه العبارة على أن اسم الجدول هو `if`. جرّبته على الملفين، وأعطى `if` في الاثنين.
4. فأضاف المحرر في آخر الاستعلام أمراً مثل `alter table if enable row level security`، ففشل لأنه لا يوجد جدول اسمه `if`.
5. **أعدت إنتاج الخطأ نفسه بالحرف محلياً:** محاكاة هذا السلوك على v2 تعطي `ERROR: relation "if" does not exist`، وعلى v3 لا يظهر أي خطأ (الأداة: `local-test/studio_rls_sim.js`).
6. **لماذا لم تكشفه الاختبارات السابقة؟** لأنها شغّلت الملف مباشرة على PostgreSQL، بدون المحرر الذي يعدّل النص قبل إرساله.
7. **ما لم أره مباشرة:** لا وصول لي إلى Supabase Studio لأرى الأمر المضاف بعيني. التفسير مبني على نمط البحث الرسمي، وعلى إعادة إنتاج الخطأ بالحرف.

## تأثير خيار RLS

- **في الحالتين، لا تغيير على RLS في جداولك الحالية:** الخيار يتعلّق فقط بالجداول التي **ينشئها** الاستعلام الذي تشغّله. استعلام التصدير لا ينشئ أي جدول.
- **المناسب: اترك الخيار «RLS Enabled» كما هو**، وهو الافتراضي والأكثر أماناً. النسخة v3 لا تحتوي أي نص يشبه إنشاء جدول، فلن يضيف المحرر شيئاً.
- **عمود `user=` في الصف الأول:** يُظهر الدور الذي نُفّذ به الاستعلام، والمتوقع `postgres`.
- **عمود `buckets=`:** يُظهر عدد Storage buckets التي رآها الاستعلام. إذا كان `0` وأنت ترى buckets في Dashboard، أخبرني قبل أي خطوة أخرى.

## ما تغيّر في v3

1. **لا توجد أي عبارة يلتقطها المحرر:** لا `create table`، ولا `alter`/`drop`/`grant`/`revoke`/`insert`/`delete`/`update` بشكل مقروء. الكلمات تُكتب مقطوعة برمز `§`، وتُجمّع وقت التشغيل بـ `replace(…, '§', '')`. فحصت الملف بأنماط المحرر، فلا يوجد أي تطابق.
2. **النتيجة مضغوطة:** 40 أمراً في كل صف، أي حوالي 25 إلى 40 صفاً. هذا بعيد عن حد عدد الصفوف في المحرر، الذي قد يقطع النتائج الطويلة.
3. **الصف رقم 0 للتحقق:** فيه عدد الأوامر، وعدد الصفوف، وبصمة md5 للتصدير كاملاً، والدور المستعمل، وعدد الجداول والدوال والسياسات وbuckets. أداة التحويل تتحقق أن الملف المحمّل كامل ولم يتغيّر.
4. **ما بقي كما هو:**
   - كل الملف أمر `SELECT` واحد، بفاصلة منقوطة واحدة في آخره.
   - لا فواصل عليا في التعليقات.
   - نُفّذ داخل جلسة للقراءة فقط بلا أي خطأ.

## خطوات التشغيل

1. افتح Supabase Dashboard، وتأكد أن المشروع هو `axzlshimvtskkxknlwoz`.
2. اذهب إلى SQL Editor ← New query. اترك خيار **RLS Enabled** كما هو.
3. انسخ **كل** محتوى `0b_tp-structure-export.sql` والصقه، من السطر الأول حتى `limit 1000;`.
4. اضغط Run دون تحديد أي جزء من النص.
5. **النتيجة المتوقعة:** جدول بثلاثة أعمدة: `part` و`info` و`sql`. الصف `part = 0` يبدأ بـ `statements=… rows=… md5=… user=postgres …`. بعده 25 إلى 40 صفاً.
6. Download ← CSV، واحفظ الملف باسم `staging_structure_before_p0.csv`.
7. أرسل لي الملف، ومعه صورة للصف `part = 0`.

## إذا ظهر خطأ

- **إذا ظهر نفس الخطأ مرة ثالثة:** أرسل لي صورة الشاشة كاملة، وجرّب مرة واحدة خيار «Run without RLS». هذا الخيار لا يعطّل RLS على أي جدول؛ كل ما يفعله أن المحرر لا يضيف تفعيل RLS للجداول التي ينشئها الاستعلام، وهذا الاستعلام لا ينشئ شيئاً.
- **أي خطأ آخر:** أرسل لي نصه كاملاً. الملف للقراءة فقط، فالخطأ لا يغيّر شيئاً.
- لا تعدّل الملف.
