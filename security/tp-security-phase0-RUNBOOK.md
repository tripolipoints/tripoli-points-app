## أ) حفظ البنية قبل التنفيذ (بدل النسخة الكاملة)

**القرار (2026-11-11):** بيانات Staging الحالية تجريبية بالكامل، وخسارتها مقبولة. المطلوب حفظه هو بنية قاعدة البيانات والإعدادات. لا Docker ولا تغيير كلمة السر.

**أ1. تصدير البنية (قراءة فقط):**
1. افتح SQL Editor → New query.
2. الصق `0b_tp-structure-export.sql` واضغط Run.
3. اضغط Download CSV واحفظ الملف باسم `staging_structure_before_p0.csv`.
4. أرسله لي.

**ماذا يحتوي الملف:**
- الجداول والأعمدة والقيم الافتراضية.
- كل الدوال بكودها الكامل.
- القيود والفهارس والـ Triggers.
- RLS وسياساته.
- صلاحيات `anon` و`authenticated` و`service_role` وPUBLIC على كل schema وجدول ودالة، والصلاحيات الافتراضية.
- جداول Realtime.
- إعدادات Storage buckets وسياساتها.
- مهام pg_cron إن وُجدت.
- صفوف الإعدادات فقط: `app_settings` و`app_text_settings` و`categories`.

**ماذا لا يحتوي:**
- بيانات الزبائن والتجار والمحافظ والمعاملات.
- حسابات الأدمن ورموز PIN.
- كلمات السر والمفاتيح.

**ما أفعله بالملف عند استلامه:**
1. أحوّله إلى ملف `.sql` قابل للتشغيل.
2. أفحصه بحثاً عن أي مفتاح أو كلمة سر قبل حفظه.
3. أعيد بناءه على قاعدة فارغة وأقارنه بالأصل.
4. أحفظه في GitHub على فرع `feature/secure-purchase-sql` فقط.

**أ2. ما ليس داخل قاعدة البيانات، فاحفظه يدوياً من Dashboard:**
- **Edge Functions:** لكل دالة، انسخ الكود من صفحة الدالة.
- **Edge Functions → Secrets:** **أسماء** الأسرار فقط، بلا قيمها.
- **Authentication → Settings وURL Configuration:** صورة شاشة.
- **Settings → API:** قائمة الـ schemas المكشوفة (Exposed schemas).
- **Storage:** ملفات bucket `map-assets` إذا لم تكن محفوظة في مكان آخر. المرحلة 0 لا تلمس Storage أبداً.

**البوابة:**

## ب) قبل التنفيذ مباشرة (قراءة فقط)

1. **اختر وقتاً هادئاً:** لا أحد يستعمل Staging خلال التنفيذ والفحوص، حتى تبقى البصمة نظيفة.
2. **فحص الحالة:** SQL Editor → New query → الصق `1_tp-security-status-check.sql` → Run → Download CSV باسم `status_before.csv`.

3. **بصمة البيانات:** New query → الصق `0_tp-data-fingerprint.sql` → Run → Download CSV باسم `fingerprint_before.csv`.

## ج) التنفيذ

4. New query → الصق `2_tp-security-phase0-urgent.sql` **كاملاً**، من `begin;` حتى `commit;` → Run **مرة واحدة**.
5. **النجاح:** لا يظهر `ERROR`، وتظهر هذه الرسائل:
   - `phase 0: N function(s) closed to the public key`
   - `phase 0 self-check: 52 behavioural checks passed` (العدد الفعلي حسب قاعدتك)
   - `phase 0 guard: no API key gained any access; N access(es) removed`
6. **الفشل:** أي `ERROR` أو `STOP` معناه أن الملف تراجع عن **كل شيء**، فهو transaction واحدة، ولم يتغيّر شيء. **لا تعِد المحاولة ولا تعدّل الملف.** انسخ الرسالة كاملة وأرسلها لي (راجع جدول الأخطاء).
